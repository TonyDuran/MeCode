# MeCode desktop prototype

This is an **offline-by-default Electron shell** around the generated trusted-workspace preview. It preserves the draft editor, local save/reopen, and recorded fixture inspection. The integrated Run control calls a narrow experimental preload/IPC bridge only when a **packaged Linux app** has the explicit launch opt-in; Submit stays unavailable. Development launches, ordinary launches without opt-in, and macOS cannot judge through this bridge. See [BRIDGE.md](BRIDGE.md) for the contract, external prerequisites, asset verification and remaining review gates. No service or localhost port is required.

## Build and run

From `desktop/` with a current Node/npm installation:

```sh
npm ci
npm test
npm run stage
npm start
npm run make
```

`stage.cjs` copies an exact allowlist of eight manifest-verified renderer files, including `run-ui.js`, from `prototypes/trusted-workspace/` into ignored `desktop/workspace/`. It also stages three hash/size-pinned Python sidecars; the final package hook verifies their exact membership/bytes and the app-bound verifier inside ASAR. Re-stage after changing the workspace. Do not edit staged files or regenerate sidecar pins without review. `npm start` remains an offline development shell, not a judge-enablement route. `npm run make` creates a platform-specific ZIP under `desktop/out/make/`; it includes Electron, so the recipient does not need a separate Electron or Node install. The Linux x64 and macOS arm64 packages can be generated on this Linux host, but **the macOS package is unsigned, unnotarized and not runtime-tested on an M1 Mac**. Fuse flipping invalidates the upstream arm64 framework's ad-hoc code signature: **the extracted app will refuse to launch on Apple Silicon until it is locally re-signed**; “Open Anyway” alone cannot repair that signature. For owner-controlled UAT only, after extracting the ZIP on a Mac, run `codesign --force --deep --sign - MeCode.app` and verify the signature before launching; this does not sign or notarize a distribution. The ASAR-integrity mechanism on macOS does not authenticate an unsigned or locally re-signable distribution. On Linux it is not enforced, although ASAR-only loading remains enforced and the Node escape hatches remain disabled. This is a PoC artifact, not a public release.

## Boundary

The renderer loads only the bundled `index.html`: Node integration off, context isolation on, renderer sandbox on, a minimal two-method preload bridge, popups and non-document navigation denied, permissions denied. The generated HTML CSP disallows network connections. The desktop package contains allowlisted shell/renderer assets and three trusted Python bridge assets outside ASAR; it excludes Python test fixtures, host state and Docker sockets. Main verifies the sidecars before every admitted spawn and latches on failure without touching recovery state. The Python assets are inert on non-Linux platforms. IndexedDB remains browser-owned; its existing error/corruption behavior is displayed by the workspace. Hash checks do not authenticate a user-writable install, and a writer may race Python's later file opens. Parent paths and installed app bytes remain trusted prerequisites; no host ownership changes are made.

**Revision-specific evidence:** Earlier shell packaging and GUI records, including later independent immutable-shell QA, do not certify this integrated candidate. The prepared tree now runs Node tests including fuse configuration; the old missing-offline-dependency report is historical. Current corrections exercise real filesystem checks, mock IPC/process boundaries and tiny ASAR fixtures for both resource layouts, not a new runnable bundle, full Electron integration, live judging or Mac UAT. No sandbox bypass is allowed. Renderer R3/R4 remediation, independent security/QA, final package inspection and runtime verification remain open. The missing generation receipt remains an explicit blocked prerequisite. See BRIDGE.md for CI coverage limits and the deliberate deferral of file-protocol-fuse hardening.

## Link prevention and manual workspace recovery (private Linux slice)

The isolated preload cancels ordinary link activation (click, middle-click, modified click, Enter on a focused link, including nested/composed targets) unless the resolved URL is a hash link inside the workspace document, and shows a short on-page notice. `navigateOnDragDrop` is pinned off; popups and permissions stay denied. This is trigger prevention only, **not confinement**: scripted document replacement (e.g. `location.assign`) can still commit a foreign document, and the earlier hard UI-NAV-01 confinement failure is unchanged.

If the window stops showing the workspace, use **File > Restore saved workspace** (Ctrl+Shift+R). Main reloads only the fixed bundled `index.html` (no renderer-supplied URL, no new IPC). It is a no-op while already on the workspace or while the window is closing, concurrent activations coalesce, and a failed load shows one native error message without retrying. Only the **last acknowledged saved** draft/theme is restored; edits not yet saved may be lost, and a prior Run result is not restored. Recovery does not clear the judge latch or resume an interrupted Run. Help > About saved-workspace recovery repeats this text. A canceled close (the editor vetoes unload for unsaved text) does not disable Restore: only an actual close does. When an explicit window close or quit is blocked by unsaved text, main shows one parented native choice (fixed text, coalesced): **Keep editing** (default/Cancel; leaves the editor and Restore usable and does not claim anything was saved) or **Discard unsaved changes and quit**, which allows only that one pending close. An ordinary navigation with no close pending receives no allowance; the unload event carries no navigation/close identity, so a navigation veto coinciding with that pending discard close cannot be distinguished (residual, not confinement). A canceled quit does not re-enable Run: the judge stays shut down until the app is restarted.
